# Changelog

## v1.0

The code and data in the state used for [Paschek et al. (2021)](https://doi.org/10.3390/app11188624), *Applied Sciences*, 11(18), 8624, developed at the Kirchhoff-Institute for Physics, Heidelberg University (2017-2019). This release reproduces the simulations, Figures 1-10, and Table 1 of the paper; it contains the known errors listed below on purpose, they are fixed in the next version.

### Changes compared to the code used for the paper
Only changes needed to run the code directly on current Linux systems, none of them changes the simulated tidal accelerations:
- **CSV reader** (`src/csvdata.h`): the reader used for the paper removed the last character of every line, which is correct only for files with Windows line endings (CRLF), where it is the carriage return, and cut off a real character for files with Linux line endings (LF). It now removes a trailing carriage return if present and otherwise keeps the line, so it works with both line endings (e.g., also for tables exported from Excel), and removes spaces around column names.
- **Crash fix** in `RelevantObjects::update()` (`src/relevantobjects.h`): when a new perturber is stronger than an entry of the map holding the strongest perturbers, the weakest entry is erased while iterating over the map. If this was the current element, the iterator was used after its node was freed (undefined behavior), which crashes with current compilers and glibc. In 2018 the freed node was reused for the newly inserted perturber, so the iteration continued from there; this behavior is now emulated with well-defined code. As in the original code, the loop does not stop after one replacement, so the map can shrink below 10 entries and is refilled by the following perturbers.
- **Sorting with undefined values**: the perturbers with the largest variation are sorted with `std::sort`, which is undefined behavior if values are NaN (see the moons with a precession period of zero below). Such values are now sorted last.
- Both only affect which perturbers are written out individually and which are summed up as `other`, not the totals: with these changes the same perturbers as in 2018 are selected for all 167 objects of the simplified simulation and for 94 of 167 objects of the full simulation. The remaining differences are 1-3 of the weakest listed perturbers, as the order of NaN values in 2018 depended on the platform; among the figures of the paper this concerns only Figure 3 (A_41_Daphne, A_532_Herculina, A_747_Winchester instead of A_185_Eunike, P_2_Nix, N_9_S_2004_N_1 in the legend).
- Paths of input and output files are relative and set in the code, the interactive input of the minimal and maximal tidal value is replaced by fixed values selecting all objects (0 and 1 m/s<sup>2</sup>).
- The simplified version of the simulation (only semi-major axis and mean motion), formerly a separate modified copy of `main.cpp`, is selected with `./solar_system --simplified` (`Body::simplify()`).
- The functions shared by the simulations moved to `src/simulation.h`, the setup of TRAPPIST-1 (by Arthur Roßmann) is added as `trappist-1/main.cpp` with its output files named after the actual time step (`delta_t_0_05d_...`).
- Input data of the solar system and TRAPPIST-1 added, with Linux line endings (`.gitattributes` keeps them on all systems). For the files with Windows line endings, the new CSV reader reads exactly the same values as the old one. The only file with Linux line endings, `moons_TNOs_v2.csv`, was read by the old reader with the last digit of the epochs of Dysnomia, Namaka, and Hi'iaka cut off (245154 and 245461 instead of 2451545 and 2454615); to reproduce the paper, these values as effectively used are given in the file (see `solar_system/data/README.md`).
- `Makefile` to build, run (`make run`), and plot (`make figures`, `make plots`).
- Plotting: `plotting/plot_tidal_acc.py` is the four-panel version used for the paper (including A<sub>total</sub>·ΔA<sub>total</sub>/Δt), `plotting/paper_figures.py` reproduces Figures 1-10 and Table 1 from the simulation results and the classification of the objects by their known volcanism and subsurface oceans based on the scientific literature (`plotting/paper_data/`).

### Verification
- Solar system, full orbital elements: all 167 result files agree with the original results of January 2018 to a relative precision of 10<sup>-12</sup>.
- Solar system, simplified orbital elements: all 167 result files agree with the original results of April 2018 to 10<sup>-12</sup>.
- TRAPPIST-1: agrees with the original results of March 2018 to 4 × 10<sup>-6</sup> (calculated on Windows at the time).
- 153 of 155 values of {A<sub>total</sub>·ΔA<sub>total</sub>/Δt}<sub>max</sub> shown in Figures 5-7 and Table 1 agree with the published values (see `figures/reproduction_check.csv` after `make figures`); the exception is Venus, see below.

### Known errors (fixed in the next version)
- **True anomaly** (`Body::calc_true_anom()` in `src/body.h`): the conversion from eccentric anomaly *E* to true anomaly *ν* is implemented as *ν* = 2 arctan(√((1+*e*)/(1+*e*)) tan *E*), which reduces to *ν* = 2*E* (modulo 2π), instead of *ν* = 2 arctan(√((1+*e*)/(1-*e*)) tan(*E*/2)). With this error every object passes through its orbit twice per orbital period, so the positions, and therefore the tidal accelerations calculated from them, are incorrect. This affects all results of the paper and the version distributed via the [software page of the Kirchhoff-Institute for Physics](https://www.kip.uni-heidelberg.de/biophysik/software.php/tidal_accelerations).
- **Epochs of the moons of TNOs**: due to the CSV reader used for the paper, the epochs of Dysnomia, Namaka, and Hi'iaka were read without their last digit (245154 and 245461 instead of 2451545 and 2454615), which shifts the orbital phase of these moons. These values are kept in `solar_system/data/moons_TNOs_v2.csv` of version 1.0.
- **Venus in Figures 5 and 6 of the paper**: Venus is simulated with both step widths (90 and 0.25 days); Figures 5 and 6 show the maximum of the 90-day run only (2.17 × 10<sup>-14</sup> m<sup>2</sup>/(s<sup>4</sup> d)), while the maximum of both runs is 9.43 × 10<sup>-14</sup> m<sup>2</sup>/(s<sup>4</sup> d), as used for Figure 7. The reproduced figures show the latter value. This does not change any conclusion of the paper.
- **Time step of TRAPPIST-1 in the paper text**: Section 2.3 of the paper states a step size of 0.1 days, but 0.05 days (1800 iterations, 90 days in total) was used, as stated in the caption of Figure 10.
- **Moons with a precession period of zero**: `period_to_d()` treats only an empty entry as "no precession", a period of `0.000` gives an infinite rate. The orbits of Nix, Kerberos (both Pluto), and S/2004 N 1 (Neptune) are therefore undefined (NaN, the solver of Kepler's equation prints "Finding root failed with requested accuracy!"), and their tidal accelerations are set to zero, i.e., these three small moons are effectively not included in the results.
- **Selection of the strongest perturbers**: the map of the strongest perturbers can shrink and be refilled by weaker ones (see above), so the 10 objects written out are not always the 10 strongest ones.
- Some functions can reach their end without returning a value (compiler warnings), which is harmless for the values used.
